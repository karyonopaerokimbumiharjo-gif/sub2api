# Sub2API 0.2.8 生产整合

本分支保留上游 v0.2.8 更新，并合入现有 CPA / Pi 运行后端与管理界面修复。

## 登录身份与模型目录修复

同一团队工作区可以包含多个独立登录用户。导入去重、Pi 凭证复用、重新授权及数据库唯一索引现在同时核对工作区与登录主体，不再仅按工作区合并账号。已配置的共享 Pi 别名也必须匹配实际凭证拥有者；凭证刷新拒绝意外返回另一位用户的身份。

Pi 模型目录使用网关当前配置的客户端版本，避免旧版本固定返回不完整的模型列表。测试弹窗保留真实上游目录与账号映射，并优先选择可用的 GPT-6 对话模型。

新导入账号默认并发容量为 4；导入时的账号优先级遵循“数值越小越优先”，与实际账号调度一致。已有账号的手动容量和优先级不由重复导入重置。账号名称已包含邮箱时，列表不再重复显示同一邮箱。

托管 CPA 账号的名称不再链接到服务器内部地址，也不再显示内部地址的悬浮提示。

相关验证包含同工作区不同用户的导入回归、PostgreSQL 真实唯一索引测试、模型目录版本传递测试，以及账号容量、优先级和测试弹窗的界面回归。

## 一次完成账号导入

账号导入界面将分组和启用设置交给后台在同一次请求中完成。只有返回已确认的账号 ID 后才显示导入成功；授权回调在失败重试时不会被重复兑换。高级设置默认折叠。

同一身份重复授权复用原账号。已有 Pi 账号更新实际凭证归属行，保留调用后端、归属用户、计费、并发和原分组，并清理旧 Token 缓存。共享 Pi 账号仍只引用同一凭证归属行，不保存第二份轮换密钥。身份不一致或并发刷新未结束时明确报错，不覆盖另一身份。

旧的只导入凭证的 API 调用可继续省略 `group_ids`；账号导入界面提供 `group_ids`，由服务端完成账号关联和启用。非 OpenAI 原生 CPA 文件仍由旧凭证接口处理，不伪装成 OpenAI 账号。

## 其他整合修复

- 修复 Pi 的流终止、正常长响应和 Chat 文本/工具完成快照处理；指定工具选择正确转换为上游格式。
- 未选择代理的用户导入采用默认出口，凭证面板严格匹配账号，代理列表分别说明测试出口和保存绑定。
- 统一审核事件明确标注旧审核、原生审核、未审核记录和上游反馈；保存有长度限制并脱敏的送审内容，不补造历史正文。
- 审核结果和审核耗时仅由管理员使用记录接口返回，用户页面及接口不暴露这些字段。
- 保留额度刷新中独立的积分缓存写入结果，避免一项展示缓存失败阻止另一项更新。

## 2026-09-27 审计规则恢复与管理入口

旧实现的 CTF 固定规则和 539 项仓库名单可追溯到提交 `668d894407d06ede7ceff4a834fd21f011b0265e`。本次恢复该名单及匹配器，新增共用的 `operator_policy_enabled` 管理开关；规则在分组筛选、用户豁免和普通审核模式之前执行。名单是历史快照，不代表覆盖未来所有仓库；名单仅保存标识和公开说明，不包含攻击载荷。

明确选择原生或本地审核后，仅调用选中的输入审核模型。规则提前拒绝的事件仍标记实际选择的审核来源。本地命中使用共用的通知、违规计数、拦截提示及关键词设置；通知伴随记录不再作为第二条审核事件显示。同一进程中相同请求和内容的前台/后台命中在十分钟内合并通知。

原生 Jev 在同一次输入判断中使用原有 13 类内容规则、所选十类意图规则和 B0–B4 生物分级。B1 输出通过原生 Jev 检查后交付，B2 保持待复核，B3/B4 拦截。OpenAI moderation 接口本身仍只有原生类别，无法代替 Jev 扩展分类。Jev 不识别图片；当前固定规则读取请求文字、元数据与有界的纯文本 data URL，不主动抓取外部附件。

统一事件支持按用户邮箱大小写无关完整匹配，列表、统计、聚合和删除预览使用同一条件。原生日志详情加载管理员事件详情中的请求/送审内容。保留 65,536 字符的上限与敏感字段/二进制媒体脱敏；超限保留头尾并标记截断。未留存的历史全文不补造。通过事件由原生 `record_non_hits` 控制，失败始终记录；采样/范围外/无可审核输入会明确记录为未送审。日志队列满时同步降级保存，不静默丢弃。

验证：安全审核包及 TypeSafe 协议包通过；隔离 PostgreSQL 验证统一查询、来源、邮箱与删除边界；原生分级/关键词/通知去重测试通过；前端 75 项相关测试及构建通过。扩大测试暴露已有的通用服务 CPA 测试夹具地址限制和无关前端日期/账号旧断言，不将这些计为本次通过项。


## 2026-09-27 Jev 分类去重与来源分组

原生引擎的清单统一为 **21 项：Sub2API 0.2.8 原版 13 类 + 本站新增 8 项**。新增项包括生物/化学风险、隐私/凭据泄露、欺骗/胁迫/剥削、政治恐吓/打压/监控、版权侵权、越狱/提示注入六类风险，以及 CTF、破甲库两项全局规则。页面提供全部勾选，原版与非原版分别标明。原有十类本地模型配置保留独立使用。

删除原生调用中重复的 `intent_violent`、`intent_non_violent_illegal_acts`、`intent_sexual_content_or_sexual_acts`、`intent_suicide_and_self_harm` 四组宽泛提问，保留原版 13 类的细分规则与阈值，不再 13+10 并列调用。全选时最多 21 个问题，全部在一次输入审核中提交；B1 必需的输出审核仍独立执行。Noul 每项判断一个条件并支持同请求批量提交，契约参考 [TypeSafe Noul 文档](https://docs.typesafe.ai/primitives/noul)。

`native_risk_categories` 是持久化的实际选择，分类目录及来源由后端返回；请求、模型评分、管理端测试及两个固定规则都遵循该选择。缺少新字段的旧配置保留原始覆盖范围，旧客户端的全局总开关仍可开关两条规则。未勾选类别不会因为评分缺失且阈值为零而被误判命中。手动关键字拦截独立生效，不随分类勾选自动删除。

规则版本为 `content-deduplicated-21-v3`；新原生日志记录实际问题数和所选分类，以便核对。分类去重不代表模型判断永远准确，也不声称目录覆盖所有未来仓库。
