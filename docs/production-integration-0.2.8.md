# Sub2API 0.2.8 生产整合

本分支保留上游 v0.2.8 更新，并合入现有 CPA / Pi 运行后端与管理界面修复。

## 一次完成账号导入

账号导入界面将分组和启用设置交给后台在同一次请求中完成。只有返回已确认的账号 ID 后才显示导入成功；授权回调在失败重试时不会被重复兑换。高级设置默认折叠。

同一身份重复授权复用原账号。已有 Pi 账号更新实际凭证归属行，保留调用后端、归属用户、计费、并发和原分组，并清理旧 Token 缓存。共享 Pi 账号仍只引用同一凭证归属行，不保存第二份轮换密钥。身份不一致或并发刷新未结束时明确报错，不覆盖另一身份。

旧的只导入凭证的 API 调用可继续省略 `group_ids`；账号导入界面提供 `group_ids`，由服务端完成账号关联和启用。非 OpenAI 原生 CPA 文件仍由旧凭证接口处理，不伪装成 OpenAI 账号。

## 其他整合修复

- 修复 Pi 的流终止、正常长响应和 Chat 文本/工具完成快照处理；指定工具选择正确转换为上游格式。
- 未选择代理的用户导入采用默认出口，凭证面板严格匹配账号，代理列表分别说明测试出口和保存绑定。
- 统一审核事件明确标注旧审核、原生审核、未审核记录和上游反馈；保存有长度限制并脱敏的送审内容，不补造历史正文。
- 审核结果和审核耗时仅由管理员使用记录接口返回，用户页面及接口不暴露这些字段。
- 保留额度刷新中独立的积分缓存写入结果，避免一项展示缓存失败阻止另一项更新。
